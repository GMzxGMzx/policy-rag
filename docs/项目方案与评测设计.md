# 工程政策合规问答系统 · 项目方案与评测设计

> 项目方案与评测设计，用于面试讲解与评审沟通。
> 技术实现见同目录 `../README.md`，可运行代码见仓库。

---

## 一、一句话

面向建筑与工程领域的政策问答系统：把政策文件切到「条」这一可引用粒度，用混合检索找证据，强制回答带可反查的引用，证据不足时直接拒答。

---

## 二、问题定义

政策问答和通用问答的根本差别：**错一个条款的代价，远高于说一句"查不到"。**

具体表现为四个约束，它们决定了系统形态：

| 约束 | 现实表现 | 对系统的影响 |
|---|---|---|
| 引用必须精确 | "第五条规定…"错成"第六条"，结论就是错的 | 切分必须到条，且引用可反查 |
| 必须会拒答 | 题库里没有的问题，模型会编一个像样的答案 | 需要显式拒答规则 + 拒答指标 |
| 时效性 | 新旧文件并存，旧文件已废止 | 需要失效识别与提示 |
| 语料不干净 | 政务 PDF 大量是扫描件；同一份文件有多个版本 | 需要语料体检环节 |

第三条最容易被忽略：一个自信引用了失效条款的系统，比查不到的系统更危险。

---

## 三、目标与非目标

**目标**
1. 回答能追溯到具体条款，且引用可被程序校验
2. 证据不足时明确拒答，而不是给出看似合理的猜测
3. 效果可度量、可回归——改动一版就能看出改善了哪一环
4. 可私有化部署，模型可替换（甲方常有"数据不出网"要求）

**非目标**
- 不做通用问答（只答语料覆盖范围内的问题）
- 不做多轮对话（当前是单轮，指代消解是后续迭代）
- 不追求排行榜式的高分，优先保证"不误导"

---

## 四、用户与场景

| 用户 | 典型问题 | 关键诉求 |
|---|---|---|
| 企业经办人 | "信用等级怎么算？扣分情形有哪些？" | 要具体分值和依据，能拿去解释 |
| 基层监管人员 | "核查周期多久？结果在哪公布？" | 要现行有效条款，不能引旧文件 |
| 产品 / 实施人员 | "某个计分规则到底怎么折算？" | 要原文，不要转述 |

三类用户的共性是：**他们都要"依据"，不是"答案"**。这决定了引用优先级高于文采。

---

## 五、核心设计（四个决策）

### 1. 条款级切分，而不是固定长度

政策的「第X条」是法律上可独立引用的最小单位。固定长度切分会把一条完整规则劈开，引用必然错位。

但真实语料不止一种结构。跑完 13 份文件发现：能解析的 6 份里，只有 1 份用「第X条」，其余分别用「一、二、三」、「1. 2. 3.」，以及评分表的「附件N」。**只认条号的解析器只能救活一小半。**

因此解析层同时支持三种引用单位，并处理：PDF 硬换行回流、附件硬边界（否则最后一条吞掉 20 页附件，实测出现单条 6417 字的畸形条款）、标题只从正文之前的区段取（否则会把「根据《XXX》」里引用的文件当成本文标题）。

### 2. 混合检索 + RRF，而不是只用向量

- 精确查询（文号、"第X条"、专有名词）：BM25 明显更强，向量会把文号当噪声
- 口语化改写（"工钱能不能发现金" vs 原文"不得以现金方式发放"）：只有向量能命中

两路用 RRF 融合，只看名次不看分数，天然解决分数不可比的问题，也不需要训练。

### 3. 引用后置校验，而不是靠提示词

提示词约束不可靠。所以生成之后再做一道程序校验：把回答里的每个 `【《文件》第X条】` 拿去和本次召回集比对，对不上的记入 `invalid_citations` 并直接判为该样本失败。

**"编条号"这个最常见的幻觉，由此从"看起来像"变成可度量、可回归的指标。**

### 4. 抽取式降级基线

无大模型时，系统返回命中的原文条款，不做归纳。

这是刻意设计的：**让检索质量能被单独评测，不被模型润色掩盖**。它也顺带证明了一件事——见第八节。

## 六、评测体系设计

### 6.1 为什么不能用单一"准确率"

一个准确率无法回答"这次改动到底改了哪一环"。所以指标分三层：

| 层 | 指标 | 含义 | 低了说明什么 |
|---|---|---|---|
| 检索 | Recall@k（文档/条款） | 正确答案是否进了前 k 条 | 切分粒度、分词、embedding |
| 检索 | MRR@k | 正确答案排第几 | 排序，不只是有没有 |
| 决策 | 应拒答·正确拒答率 | 没答案时有没有老实说不知道 | 拒答规则太松（最危险）|
| 决策 | 可答·误拒答率 | 有答案却拒答 | 拒答规则太严 |
| 引用 | 引用有效率 | 引用能否在召回集反查到 | 模型在编条号 |
| 引用 | 要点命中率 | 标准答案关键词覆盖 | 生成内容不全 |

### 6.2 评测集构成

25 条，按难度与类型分层，不是随机抽样：

| 类别 | 条数 | 设计意图 |
|---|---|---|
| 条例体（第X条）| 6 | 基础能力 |
| 通知体（一、二、三）| 5 | 检验多结构支持 |
| 评分标准（附件）| 4 | 检验数字与附表定位 |
| 统计数据 | 3 | 长条款拆块后是否仍能命中 |
| 时效性 | 1 | 区分发布日期与施行日期 |
| 应拒答 | 3 | 检验会不会编 |

**应拒答样本是必须单独设计的一类**：分别覆盖"语料完全没有的主题""跨地区""时间上不存在"三种编造诱因。

### 6.3 Badcase 六类归因

失败不能只说"答错了"，要归到可行动的位置：

| 类别 | 含义 | 该改哪里 |
|---|---|---|
| A | 该拒答却作答 | 拒答规则 / 检索分阈值（最高优先级）|
| B | 检索未命中导致误拒答 | 切分 / 分词 / embedding |
| C | 召回到了却拒答 | 提示词过严 |
| D | 引用了不存在的条款 | 引用格式约束 |
| E | 答案对但条款没召回 | 运气命中，不可靠 |
| F | 要点覆盖不足 | 生成内容 |

### 6.4 回归流程

每次改动跑一遍，与基线对比：

```bash
python -m scripts.evaluate --baseline <上次的 metrics.json> --tag v2
```

报告输出「本次 / 基线 / 变化」三列带升降标记，能直接看出是改善了检索、还是牺牲了拒答。

## 七、真实数据验证

**语料**：13 份真实政策文件（江苏省 / 苏州市 / 徐州市住建、人社条线）

| 环节 | 结果 |
|---|---|
| 可直接抽文本 | 6 份（46%）|
| 纯图片扫描件 | 7 份（54%），需 OCR |
| 切分结果 | 88 条 → 127 个检索块 |

**评测结果**（25 条样本，hash embedding + 抽取式，无大模型）

| 指标 | 值 | 说明 |
|---|---|---|
| Recall@5 文档 | 1.00 | 18/18 命中正确文件 |
| Recall@5 条款 | 1.00 | 18/18 命中正确条款 |
| MRR@5 | 0.947 | 19 条排第 1 |
| 引用有效率 | 1.00 | 修复前为 0.33 |
| 可答误拒答率 | 0.00 | |
| 应拒答正确拒答率 | **0.00** | 抽取式模式不会拒答 |

**最有价值的一次修复**：引用解析最初只认「第X条」，导致通知体（引用单位是「一、核查周期」）和附件（「附件1」）的引用全部被判为无效，引用有效率只有 0.33。改成"拿上下文里真实存在的条号去回答里找"之后，升到 1.00。

## 八、这个基线证明的一件反直觉的事

抽取式基线：**检索召回 100%，拒答率 0%。**

也就是说——检索全对了，系统依然不可用。它会把不相关的条款当成答案端出去。

结论：**检索对 ≠ 系统可用。** 大模型在合规场景的价值主要不在润色文字，而在**判断该不该答、该怎么划定证据边界**。这正是做降级基线的目的：先证明必要性，再谈优化。

---

## 九、已知边界（面试主动说）

1. **样本规模小**：127 块、25 条，Recall=1.0 说明评测框架跑通了，说明不了效果好
2. **7/13 语料是扫描件**：导出工具已就绪（63 张图），但 OCR 本身未接入，语料量受限
3. **矢量描边 PDF**（印刷稿）无法导出图片，需外部渲染器
4. **embedding 用的是无语义 hash 模式**：能拿到 1.0 主要靠 BM25 在中文条款上本身强 + 样本少
5. **附录类附件会污染检索**：实测附件里有行政区划代码表，数字密度高、易误命中
6. 引用只到条/节，不到「款」；表格附件按文本处理，结构会丢

## 十、迭代路线

| 优先级 | 事项 | 目的 |
|---|---|---|
| P0 | 补齐 OCR，纳入 7 份扫描件 | 语料翻倍，样本才有统计意义 |
| P0 | 评测集扩到 100+ | 补新旧版本冲突、跨文件引用、地区差异 |
| P1 | 换 BGE-M3 + reranker，做消融 | 分别度量 BM25 / 向量 / 重排的边际贡献 |
| P1 | 检索分阈值前置拒答 | 把 A 类 Badcase 压到 0 |
| P2 | 表格附件结构化 | 评分表按行解析成字段 |
| P2 | 权限过滤 | 不同角色可见政策范围不同，政企硬需求 |

## 附：如果被追问

**"127 个块也好意思说 Recall 1.0？"**
承认。这个项目的产出是**评测框架和解析器**，不是效果数字。效果要等 OCR 补齐、语料上万条后重跑，我现在不会拿小样本的 1.0 说事。

**"这和直接调 Dify 有什么区别？"**
Dify 解决编排，不解决两件事：一是把真实政策文件切到可引用的粒度（三种结构、附件边界、扫描件）；二是把"引用是否可反查"变成可回归的指标。这两件恰好是这个场景的主要工作量。

**"为什么不用现成的评测工具？"**
通用 RAG 评测框架不区分"检索没召回"和"召回了但拒答"。而这个场景恰恰最需要区分——前者改切分，后者改提示词，方向完全不同。
